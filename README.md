# PPW Bench — производительность на ватт

[![Python](https://img.shields.io/badge/python-3.9%2B-blue)](https://www.python.org/)
[![Platform](https://img.shields.io/badge/platform-Windows%20%7C%20Linux-lightgrey)](#требования)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)
[![CI](https://github.com/Dimak25/ppw-bench/actions/workflows/ci.yml/badge.svg)](https://github.com/Dimak25/ppw-bench/actions/workflows/ci.yml)

**Русский** | [English](README.en.md)

Замеряет **PPW (Performance per Watt)** процессора: сколько работы CPU выполняет
в секунду на каждый потреблённый ватт.

```
PPW = (работа / секунда) / (средняя мощность, Вт)
```

Один скрипт запускает детерминированную нагрузку на C, параллельно снимает
реальную мощность CPU (RAPL) и сохраняет отчёт в `.txt`. Мощность берётся из
счётчиков Windows или из `powercap` в Linux. Создан для Intel Core Ultra 9 185H,
но работает на любом ПК/ноутбуке с Windows или Linux, где доступны счётчики
энергии (Intel, AMD Zen).

## Возможности

* Нагрузка на C (Win32-потоки / pthreads): целочисленные цепочки + плавающая
  точка, одинаковый объём работы на любой машине — баллы сравнимы между
  прогонами. Версия компилятора пишется в отчёт.
* Многопоточная и однопоточная фазы.
* Мощность: RAPL (пакет CPU и ядра) + мощность системы как fallback
  (`Power Meter` в Windows, `psys` / батарея в Linux). В Linux используется сам
  счётчик энергии (ΔE/Δt) — это точнее усреднения сэмплов.
* Пауза на охлаждение между многопоточной и однопоточной фазами.
* Корректный учёт прогрева: буст PL2 отбрасывается, считается установившийся режим.
* Показатель стабильности (разброс мощности и скорости) — видно, можно ли верить цифрам.
* Предупреждения: работа от батареи, энергосберегающая схема/профиль, фоновая нагрузка.
* Отчёт в `.txt` (в Windows — UTF-8 с BOM, нормально открывается в Блокноте).
* Без внешних Python-зависимостей.

## Требования

### Windows

* Windows 10/11.
* Python 3.9+ (`py` или `python` в PATH).
* **gcc** — MinGW-w64 или TDM-GCC (`gcc --version`).
  `bench.exe` собирается автоматически при первом запуске.

### Linux

* Любой дистрибутив x86_64, ядро с `intel_rapl_common` (Intel, AMD Zen).
* Python 3.9+ (`python3`) и `gcc` — или готовый релиз, см. ниже.
* Доступ к RAPL: с ядра 5.10 `energy_uj` читает только root, поэтому запуск
  через `sudo` или один раз установить udev-правило (см. [Linux](#linux)).

Для честного замера: питание от сети, схема «Сбалансированная» или
«Высокая производительность» (в Linux — `powerprofilesctl set balanced`),
закрытые лишние программы.

## Установка

```bat
git clone https://github.com/Dimak25/ppw-bench.git
cd ppw-bench
py ppw_bench.py
```

Сборка выполнится сама. Вручную:

```bat
gcc -O2 -static bench.c -o bench.exe
```

## Linux

Из репозитория:

```bash
git clone https://github.com/Dimak25/ppw-bench.git
cd ppw-bench
sudo python3 ppw_bench.py --quick   # bench соберётся через gcc сам
```

Готовые сборки на странице [Releases](https://github.com/Dimak25/ppw-bench/releases/latest):

* `ppw-bench-vX.Y.Z-linux-x86_64.tar.gz` — скрипт + статический `bench`
  (~400 КБ). Нужен только `python3` ≥ 3.9, он есть почти в любом дистрибутиве.
* `ppw-bench-vX.Y.Z-linux-x86_64` — самостоятельный бинарник (Nuitka), Python
  не нужен (~4 МБ, glibc ≥ 2.35: Ubuntu 22.04+, Debian 12+, Fedora 36+).

```bash
tar xzf ppw-bench-v*-linux-x86_64.tar.gz
cd ppw-bench-v*-linux-x86_64
sudo ./ppw-bench --quick
```

```bash
chmod +x ppw-bench-v*-linux-x86_64
sudo ./ppw-bench-v*-linux-x86_64 --quick
```

При запуске через `sudo` отчёт передаётся вашему пользователю, а не root.

### RAPL без sudo (udev)

Правило даёт право чтения `energy_uj` только группе `powercap` (не всем:
доступ к счётчикам закрыт из-за атаки Platypus, CVE-2020-8694), а скрипт
добавляет вас в эту группу:

```bash
sudo ./install-udev.sh        # в репозитории: sudo packaging/linux/install-udev.sh
```

После этого перелогиньтесь (или выполните `newgrp powercap`). Удаление:
`sudo ./install-udev.sh --uninstall`.

## Portable-версия для Windows (без Python и gcc)

Готовые сборки лежат на странице
[Releases](https://github.com/Dimak25/ppw-bench/releases/latest) — Python и gcc
для них не нужны.

* `ppw-bench.exe` — один файл, самый удобный вариант.
* `ppw-bench-vX.Y.Z-win64-portable.zip` — папка с exe и `_internal`
  (**рекомендуется, если антивирус ругается на одиночный exe**).

1. Скачайте `ppw-bench.exe` или ZIP-архив.
2. Запустите двойным щелчком или из терминала:

   ```bat
   ppw-bench.exe --quick
   ```

3. Отчёт `ppw-report-*.txt` сохранится рядом с exe.

### Если антивирус пишет Trojan:Win32/Wacatac.H!ml

Это известное ложное срабатывание эвристики на неподписанные onefile-сборки
PyInstaller. В программе нет сетевого кода и посторонних файлов.

1. Сверьте SHA256 скачанного файла с `SHA256SUMS.txt` из релиза.
2. Используйте ZIP-сборку — она реже попадает под такие эвристики.
3. Отправьте файл в Microsoft как false positive:
   <https://www.microsoft.com/en-us/wdsi/filesubmission>.
4. При необходимости добавьте папку с программой в исключения Defender.

> exe не подписан цифровой подписью, поэтому SmartScreen также может показать
> предупреждение «Неизвестный издатель». Это ожидаемо для открытой сборки:
> сверьте SHA256 с `SHA256SUMS.txt` из релиза.

## Использование

```bat
py ppw_bench.py                 :: 60 с на фазу, MT + ST
py ppw_bench.py --quick         :: 20 с на фазу
py ppw_bench.py --duration 120  :: стабильнее (PL1)
py ppw_bench.py --list          :: показать датчики мощности и выйти
```

Или двойной щелчок по `run.bat` / `ppw-bench.exe`.

Без аргументов запускается интерактивное меню: показать датчики мощности,
быстрый тест (20 с), обычный (60 с) или длительный (120 с). После теста
приложение спросит, сохранять ли `.txt`-отчёт, и не закроет окно сразу.

| Параметр | Описание |
|----------|----------|
| `--duration N` | секунд на фазу (по умолчанию 60; 120 — стабильнее) |
| `--quick` | быстрый режим: 20 с на фазу |
| `--threads N` | потоков в многопоточной фазе (по умолчанию — все) |
| `--no-st` | только многопоточная фаза |
| `--only-st` | только однопоточная фаза |
| `--cooldown N` | пауза между фазами, с (по умолчанию 10; 0 — без паузы) |
| `--pin MODE` | ядра для однопоточной фазы: `auto` (по умолчанию), `p`, `e`, `lpe`, `all` (отдельная фаза на каждом типе ядер), `none` или список CPU (`0,2,4-7`) |
| `--repeat N` | повторить каждую фазу N раз; в отчёте медианы и разброс между прогонами |
| `--watts N` | считать PPW по заданной мощности (если датчиков нет) |
| `--out FILE` | путь к `.txt`-отчёту (по умолчанию `ppw-report-*.txt`) |
| `--list` | показать найденные датчики и выйти |
| `--interactive` | запустить интерактивное меню |
| `--version` | показать версию и выйти |

### Гибридные CPU и повторы

У гибридных процессоров (Intel 12-го поколения и новее, Core Ultra, AMD
Zen 5 + Zen 5c) ядра разные: P (производительные) и E (энергоэффективные).
Планировщик ОС переносит однопоточную нагрузку между ними, поэтому ST-результат
может прыгать на 10 % от прогона к прогону.

* `--pin auto` (по умолчанию) — на гибридном CPU ST-фаза идёт только на
  P-ядрах, на обычном ничего не меняется. Какие ядра использовались, видно
  в строке «Ядра» отчёта.
* `--pin e` / `--pin lpe` — однопоточный тест на E- или LP-E-ядрах
  (LP-E есть у Core Ultra 1-го поколения, Meteor Lake); `--pin none` — как раньше.
* `--pin all` — однопоточная фаза по очереди на каждом типе ядер (P → E → LP-E),
  в итоге отчёта строки `ST (P)`, `ST (E)`, `ST (LP-E)`. В интерактивном меню
  это пункт 5 (появляется только на гибридных CPU).

  ```bat
  ppw-bench.exe --only-st --pin all --duration 30 --repeat 3
  ```

  Мощность — это мощность всего пакета CPU (с простаивающими ядрами и
  остальным кристаллом), поэтому PPW показывает эффективность «ноутбука на
  одном ядре такого типа», а не изолированного ядра.

  Как определяются типы: Windows — класс эффективности ядра
  (`EfficiencyClass`), Linux — `cpu_core` / `cpu_atom`. E и LP-E обе ОС часто
  относят к одной группе; их различаем по кэшу: у LP-E-ядер (на SoC-кристалле)
  нет общего с P-ядрами L3.
* `--repeat 3` — каждая фаза трижды, в отчёте медианы и строка «Повторы» с
  разбросом между прогонами. Если разница между двумя машинами меньше этого
  разброса, считайте их равными.

```bat
ppw-bench.exe --quick --repeat 3
```

## Пример вывода

```
ФАЗА 1 — MULTI-THREAD (22 поток(ов))
  Производительность : 1.541 Gед/с
  Ср. мощность CPU    : 15.92 Вт (пакет)
  Ср. мощность ядер   : 11.38 Вт (pp0)
  Ср. мощность системы: 22.03 Вт
  PPW (пакет)         : 96.772 Mед/с на Вт
  PPW (система)       : 69.941 Mед/с на Вт
  Стабильность        : мощность ±3.0%, скорость ±3.1%
```

* **Производительность** — «единицы работы» в секунду. Единица работы —
  фиксированный блок вычислений в `bench.c`, поэтому результаты сравнимы
  между машинами и прогонами.
* **PPW (пакет)** — главный результат: работа/с на ватт по мощности CPU.
* **PPW (система)** — то же по мощности всей системы (на ноутбуке от батареи).
* **Частота ядра / ядер** — реальная тактовая частота ядер под нагрузкой.
  В конце каждой фазы, не давая ядрам остыть, bench ~0,25 с крутит цепочку
  зависимых сложений (каждое — ровно 1 такт), так что «сложений в секунду» и
  есть частота. Счётчики ОС для этого не годятся: на гибридных CPU Windows
  показывает заведомо заниженные значения. В однопоточной фазе — частота и
  номер CPU, в многопоточной — среднее, на гибридных CPU отдельно по
  P / E / LP-E. Помогает понять, не держит ли схема питания ядра на низкой частоте.
* **Стабильность** — разброс в окне измерения. Больше ~10–15 % — результаты
  шумные (батарея, экономия энергии, фоновые задачи).

## Как это работает

1. `ppw_bench.py` собирает `bench.c` в `bench.exe` / `bench` (если нужно).
2. Запускает фазу: C-нагрузка печатает прогресс раз в секунду.
3. Параллельный поток читает датчики мощности:
   * **Windows**, PDH-счётчики: `\Energy Meter(*)\Power` (RAPL, пакет/ядра),
     `\Power Meter(*)\Power` (система);
   * **Linux**, `powercap`: `intel-rapl:N/energy_uj` (`package-N`), подзона
     `core`, `psys`; как fallback — `power_now` батареи.
4. Берётся окно после прогрева, в нём усредняются мощность и скорость.
5. `PPW = работа/с ÷ ватты`, отчёт пишется в `.txt`.

## Если PPW не считается

* `--list` пустой или «датчики PDH не найдены» — нет провайдера `Energy Meter`.
  Используйте `--watts N` (мощность CPU в ваттах) или внешний ваттметр.
* Датчик есть, но PPW пустой — он вернул 0; проверьте `--list`.
* `Не найден компилятор C` — установите MinGW-w64/TDM-GCC (Windows) или `gcc`
  (Linux), либо возьмите готовый релиз.
* Linux: «RAPL найден, но нет прав» — запустите через `sudo` или установите udev-правило.
* Linux: нет зон `intel-rapl` — `sudo modprobe intel_rapl_common`. В виртуальной
  машине RAPL обычно недоступен.

## Советы для сравнимых результатов

1. Подключите блок питания (на батарее CPU режется по мощности).
2. Схема питания: «Сбалансированная» или «Высокая производительность».
3. Закройте браузеры/IDE/сканирование антивируса.
4. Одинаковая `--duration` и одинаковое число потоков.
5. Для сравнения железа — многопоточная фаза со всеми логическими процессорами.

## CI

GitHub Actions на `windows-latest` и `ubuntu-latest` собирает `bench.c`,
запускает юнит-тесты и короткий smoke-прогон. Мощность на CI-раннерах недоступна, поэтому там PPW = n/a —
проверяется сама работоспособность пайплайна.
